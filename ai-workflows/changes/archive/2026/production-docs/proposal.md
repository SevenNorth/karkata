# 变更提案：完善官网生产接入文档

## 背景

Karkata 官网已有快速开始、Runtime 能力、Provider 和 UI 集成说明，但缺少从本地示例走向线上应用所需的生产架构、安全、配置、错误处理和部署内容。使用者容易误把浏览器直连模型、Human-in-the-Loop 或透明代理当成生产安全边界，也难以系统核对可用配置和错误恢复策略。

## 目标

- 新增五组中英文生产接入页面，覆盖架构选择、安全边界、配置参考、错误处理和部署检查。
- 让导航、页面清单、站点契约和静态构建完整识别新页面。
- 所有示例与当前 `0.1.0` 公共 API 一致，并明确服务端凭据、受限网关、SSE、取消、鉴权和限流边界。

## 范围

- 新增 `/production/architecture`、`/production/security`、`/production/configuration`、`/production/errors`、`/production/deployment` 及对应英文页面。
- 更新 VitePress 中英文导航、侧边栏、页面 manifest 和相邻入口链接。
- 基于现有 Core、OpenAI-compatible 和 UI 契约编写配置表、错误分类、部署拓扑和上线检查表。
- 修正发布文档中残留的旧 npm scope 文本。

## 非目标

- 不新增后端、网关、Dockerfile、部署工作流或真实 LLM Demo。
- 不修改 Runtime、Provider、UI 公共 API、错误码或配置默认值。
- 不承诺任意透明代理可直接用于生产；不提供真实凭据、开放代理代码或厂商专属部署模板。

## 验收标准

- [x] 官网提供五组完整镜像的中英文生产接入页面，站内可从导航和相邻指南到达。
- [x] 架构与安全页面区分浏览器直连、服务端 Agent 和受限同源网关，并明确 API Key、认证、授权、限流、SSRF 和日志边界。
- [x] 配置与错误页面准确覆盖当前公开配置、错误码、重试分类、取消/超时和安全展示策略。
- [x] 部署页面给出可执行的环境变量、反向代理/SSE、健康检查、可观测性和上线检查清单，但不假装已有后端实现。
- [x] `npm run test:docs`、`npm run docs:build` 和 `npm run check` 通过，生成的中英文路由完整。

## 风险

- 文档若超前于实现会形成错误契约，因此配置、错误和取消语义必须从源码与设计基线交叉核对。
- 代理示例若边界不清会诱导开放转发或泄露凭据，因此只描述受限网关责任，不给出任意上游 URL 转发方案。
- 页面数量增加可能造成中英文结构漂移，由 manifest 页面配对和站点契约验证控制。

## 待确认项

- 用户已明确批准先完善官网生产架构、安全、配置、错误和部署文档，不写新后端。
- 规模涉及 10 个新内容页和站点导航，但均属于一个“生产接入文档”验收目标，无独立 Runtime 或部署实现边界，保留一个 change。
